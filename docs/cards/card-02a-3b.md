## 目标

玩家本场抓到的汀蛙，点击「再来一场」后仍在携带列表中，**全部携带宠物恢复各自满血**；刷新页面则回到初始两只汀蛙。

**为什么：** 抓住的宠物不能下一场就消失；但原型阶段也不需要上存档，把数据保留在当前网页内存就足够验证“继续抓”的动力。

## 玩家能看到什么

1. 第一场初始携带 **2/5**。抓到一只后变成 **3/5**，携带列表仍能看到这只汀蛙。
2. 本场如召唤这只新抓的汀蛙，气血仍是**被抓瞬间的残血**（已由 02a-3a 实现，本卡不改变）。
3. 战斗胜利或失败后点「再来一场」，携带仍为 **3/5**；新抓的汀蛙仍是同一个实例，不被替换成初始宠。
4. 新一场该汀蛙气血为**最大生命/最大生命**，包括上一场气血为 0 的携带宠。
5. 新一场撷灵客使用现有「召唤」，能选择这只上一场抓到的汀蛙；一场只允许一只宠出战，保留每场召唤次数限制。
6. 继续抓其他汀蛙，可从 **3/5** 增至 **4/5、5/5**；满额仍无法抓，不能覆盖旧宠。
7. **刷新浏览器**后回到初始 **2/5**，不保留新抓的宠物。

**为什么：** 要明确区别“换一场战斗”和“重新打开游戏”。前者保留临时收集成果，后者清空，是当前无存档原型的边界。

## 最小实施边界

1. 将现有携带数据从“单个 `Battle` 的生命周期”延长到“本次网页会话的多场战斗”。可在创建下一场时传递**内存快照**，不可用浏览器本地存储代替。
2. 必须保存宠物**真实实例身份与战斗属性**（包括 ID、名字、等级、最大生命、攻防速、已有技能以及初始/抓获来源）；不能只拷贝携带数量，也不能给新宠套用写死的初始汀蛙模板。
3. 新战斗开始时，**复制**携带数据并统一恢复满血；不要反向修改上一场已经结束的战斗记录。重置临时战斗状态（防御、撤离、出战状态等），但不要改变原有的英雄愤怒保留行为。
4. **跨场唯一 ID：** 当前敌人常复用 `enemy-0` 等编号；`caught-enemy-0` 在两场可能重复。必须用本次网页会话内的稳定唯一规则区分不同场次抓到的汀蛙，且同一宠跨场 ID 不变。唯一规则在纯 TS 中实现，不引入新依赖。
5. 复用 `assets/logic/roster.ts`、`assets/scripts/Battle.ts`、`assets/scripts/BattleView.ts` 的现有流程；界面只显示和接收点击。`assets/logic/` 负责纯规则，`assets/scripts/config.ts` 保持唯一运行配置来源。
6. 跨场后携带列表不应把上场抓到的宠继续误标为「本场抓取」；建议统一显示「抓取获得」，初始仍标「初始」。**仅改标记文案**，不做宠物详情页。

**为什么：** 一只宠物的身份比显示名称重要：两只都叫汀蛙，也必须是两只不同的宠。恢复生命属于“新战斗初始化”，不属于抓取瞬间的奖励。

## 逻辑测试（必须实际运行）

1. 初始新会话携带数 2/5；抓到新宠后为 3/5。
2. 同场被抓的新宠残血不变；下一场所有携带宠（含残血、气血 0）都恢复各自满血，`maxHp` 不被改写。
3. 战斗胜利**或失败**后开始下一场，已抓的宠仍在，宠物 ID、等级、攻防速与来源不变。
4. 两场分别抓取编号为 `enemy-0` 的敌人，新增两个**不同 ID** 的宠物；原有宠物不被覆盖，5 只容量依然生效。
5. 上一场新抓的宠能在下一场通过现有召唤选择；默认只出战原初始宠，每场召唤次数重新计数。
6. 新建一个**全新游戏会话**时恢复初始 2/5；不需要模拟真实浏览器存储，因为本卡根本不使用持久化。
7. 下一场的状态修改不会回写到上一场的战斗快照；上一场结果与击杀／抓取区分不变。
8. 原有抓取、满员拒绝、攻防、自动战斗、召唤与胜负测试继续通过；不能删减原有断言。

## 华周怎么试玩（一次试玩会话）

1. 在 Cocos Creator 3.8.8 打开 `assets/scenes/Battle.scene`，浏览器预览；确认初始 **携带 2/5**。
2. 由撷灵客抓到一只野外汀蛙，看到 **3/5**。打开携带列表，记住刚抓到的汀蛙气血，如 `8/33`（仅举例，**不要求固定数值**）。
3. 结束本场，点击「再来一场」。打开携带列表，仍为 **3/5**，刚抓到的那只仍在，气血现在是**满血**（例如 `33/33`）。
4. 撷灵客点「召唤」，选择上一场抓到的汀蛙；能正常出战，且生命是满血。
5. 再结束战斗并「再来一场」，数量不下降。最后刷新浏览器，确认回到 **2/5**。

**人工验收重点：** 抓到的宠物不会因为「再来一场」丢失、气血能恢复、还能召唤；刷新会清空。抓取有随机性，可能需要尝试几次，不要求固定一场成功。特殊边界由逻辑测试覆盖。
