## 2. 修复与规则边界

P2-14 用两只合格的 10 级后备宝宝在旧 Web Mobile 包复现「合宠物种或必带技能配置错误」。产物把集合展开变成把整个 `Set` 拼到数组上。主线 `pet-fusion.ts` 有两处受影响，分别在 `fusionPlan` 的候选物种和 `fusePets` 的父方技能。用适配现有发布目标、保持首次出现顺序的数组去重修两处。保持过滤顺序、随机调用次数及同输入随机序列的结果语义。按结果物种放必带，重复技能只参加一次继承抽取。

| 项目 | 本卡执行口径 |
| --- | --- |
| 合宠 | 资格、同种／异种物种概率、资质与成长倍率、40% 技能继承和 8 格上限沿用主线。沿用二次确认、v6 主键与序号、成功保存后才替换双亲、失败重试同一候选。 |
| 暗雷、掉落、技能 | 暗雷保护 180、每 60 单位 10%。正式掉率 8%／3%／1%，测试 50%／30%／10%。技能、打书和还童规则沿用主线。 |
| 调试与演出 | 正常发布入口以正式掉率运行，已有开发入口仅按原门禁开放。用同一固定用例比较 ×1／×2，核对命中与动作顺序、气血和法力展示及结算一致。 |

改动范围集中在合宠纯逻辑。统一构建目标、通用集合逻辑、战斗接线、UI 与配置均在白名单之外。若收口实测暴露相邻缺陷，记录问题和复现，按项目 X2 处理范围变更。

## 4. 逻辑与产物验收

1. **先红后绿**　先用 P2-14 的旧 Web 包和隔离样本复现。新增的兼容用例复用现在的 Creator TS 测试加载方式，仅对合宠目标模块覆盖会破坏集合展开的降级路径，让同一用例在修复前失败、修复后通过。断言合法的物种候选、异种和同种分支、重复技能只保留一次且顺序正确，覆盖父方必带排除。旧包、低目标单测、新包的证据分别记录。
2. **存档和节奏回归**　运行已有 v5→v6 保值、v6 读写、合宠取消和无资格零写入、失败保双亲、同候选重试及成功只保存一次的用例。运行已有回放与掉率定向测试。对同一固定战斗的 ×1／×2 只切换表现速度，以相同随机输入核对终局、经验、掉落、保存和回场一致。同一隔离档在开发预览切正式／测试档后库存保留，开战锁定本场概率，测试状态清楚可见。
3. **双端重新构建**　按既有 Creator 3.8.8 配置串行构建 Web Mobile 和微信，核对两端产物来自同一候选源码、有实际产物且构建日志无错误。对比 P2-13 的同口径未压缩尺寸，Web 总包 8,483,737，微信总包 6,567,090、主包 919,168、battle 3,072,046、town 1,923,710、outskirts 594,500、inventory 57,666 字节。分别报实际值和差值，沿用 `docs/wechat-build.md` 的 3.5 MB 微信主包停止线。

## 5. 试玩清单

复用 P2-14 强档或等价隔离样本。准备两个档，均留第三只宠出战。一个档为两只不同物种的普通 10 级宝宝，一个档为同种 10 级宝宝；安排可重复的重叠非必带技能候选，注明实际技能、随机控制与预期。通过发布包的正常游戏入口读取隔离样本，使用既有验收手段控制样本；实际点击界面完成操作。

| 在哪点、怎么点 | 应看到什么 |
| --- | --- |
| 在**新 Web Mobile 包**用异种档进城，打开合宠并选两只后备宝宝，分别试取消和确认 | 能看到二次确认；取消保留双亲、存档无写入。确认成功后只移除两只父宠并新增一只合法结果，原出战宠不变，数据和表现与规则一致。 |
