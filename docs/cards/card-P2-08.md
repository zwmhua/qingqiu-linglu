## 1. 基线、目标与三问

核对仓库 `zwmhua/qingqiu-linglu` 主线 `760b994d0e72add9f82d8a44b1c4ae67819a0019`。P2-07 已由华周试玩验收并合入，验收提交 `9a3dbb0d15d21b97381055ed192490d546d34833`。开放 PR、Issue 均为 0。设计依据为 `docs/phase2-design.md` §3.1、§3.2、§4.1 及 P2-08 条目。

- **真实目标**　让暴击、连打、噬血、还击、反弹在己方召唤兽和敌方灵宠的普通物理攻击中生效，玩家能从血条和日志看懂发生的顺序。
- **可以砍**　复用当前普攻、受击和浮字表现。法术、主动技能入口、物种池与持久化改动留给各自的卡。
- **最可能出错**　当前 `Battle.resolve()` 按单次攻击处理扣血、保护、记录并立刻判胜负，`BattleView.playNextAttack()` 用旧血条快照串行播放。若在一击中途判胜、让反应再次触发被动，或在第一击画出整个回合后的血量，就会出现漏结算、重复反应或血条跳变。

## 2. 五项效果

技能参数读取现成的 `PET_SKILLS`。按个体已有技能 ID 判定。防御姿态、保护比例、最终速度排序和无相关技能的普攻沿用当前规则。

| 技能 | 触发与结果 |
| --- | --- |
| 暴击 `crit` | 拥有时，每次实际执行的主击独立按 10% 抽，命中本击 ×2。未拥有则概率 0，不取额外随机数。 |
| 连打 `combo` | 普攻指令执行时判一次，45% 触发。同目标最多两击，每击 ×0.75。未触发时一击 ×1。攻击者或目标倒地、离场时停止后续击，不把第二击转给其他目标。 |
| 噬血 `lifesteal` | 每次主击后，回复 `floor((原目标实际失血 + 保护者实际失血) × 0.25)`，受攻击者缺血量限制。实际失血用扣血前后差，排除超杀溢出。 |
| 反弹 `reflect` | 活着的原受击者实际失血且攻击者仍在场存活时，按 30% 判定。伤害为 `floor(原目标实际失血 × 0.25)`，允许为 0。直接扣血，跳过护甲、姿态和再次保护。 |
| 还击 `counter` | 在反弹处理之后，原受击者有技能且双方仍在场存活，按 30% 独立判定。用还击者和其目标的当前有效攻击／防御、现有物理随机浮动及 ×0.5 算伤害，并沿用目标防御姿态，最低 1。跳过再次保护。 |

**取整口径**　主击用当前物理基础算式 `(攻击 − 防御 × 0.40) × 浮动`，乘本击连打和暴击倍率后，执行现有第一次 `Math.round` 和最低伤害限制。接着照旧处理防御姿态的取整与最低值，再按现有保护规则分摊。还击的 ×0.5 放在同一首次取整位置。反弹和噬血用实际掉血值单独向下取整。概率判断用 `roll < rate`，等于阈值视为未触发。

## 3. 结算与播放顺序

1. 轮到普攻时按旧规则选择合法目标。只在第一次主击前沿用目标失效的重选逻辑。这一个普攻动作内，先抽连打，再逐击抽暴击和本击的物理浮动。
2. 每一击依次执行 **主击扣血与保护分摊 → 噬血 → 反弹 → 还击**。保护者照常扣血，原目标的反弹只看自己实际失血，保护者不因代扣触发反弹或还击。人物实际损血仍按原规则增长愤怒。
3. 主击打倒原目标，保留本击已经产生的有效吸血，原目标不反应。反弹打倒攻击者，立即停止还击和第二击。还击打倒攻击者也停止第二击。每一步更新实际血量和倒地状态。用有限的伤害来源区分主击、反弹、还击，两个反应均不会触发这五项被动，因此没有递归。无技能、无有效目标或无资格反应的分支不额外消耗技能随机数。
4. 整次普攻及有限反应结束再调用已有胜负判定。继续沿用基线的胜负优先顺序及一次经验结算，终局不再开始下一回合回血。抓取判胜、逃跑、地图往返和已验收的保存入口沿用原语义。
5. 沿用现有战斗事件队列。每一击、实际噬血、反弹、还击按发生顺序更新对应血条。被动名字在现有表现中可辨认，反弹或回血可复用现有血条和日志，无需新动画。×1／×2 均要播完并正常回到下一轮或结算页，过程中保留各事件当时的 HP，动画结束才同步回合开始回血后的状态。

**为什么按这个顺序**　每击只处理有限的反应。玩家能看到谁先掉血、何时吸血和谁倒地，第二击也能在应停的位置停住。

## 5. 逻辑测试和固定试玩

**逻辑测试**　用固定随机源验证 10%／45%／30% 阈值前后、技能实际抽取次数和等距固定样本的命中比例。确认无技能旧伤害与目标流程、连打未触发时无减伤、两击各自暴击、超杀与保护实际失血吸血、反弹先于还击、保护者有反应技能且分摊后仍存活时也不触发反应、反应不递归、倒地截断第二击。覆盖一击致死、反弹致死、还击致死及反弹 0，验证现有同归边界和经验只结算一次。复用现有视图集成测试核对事件队列可收尾和血条顺序。执行开发负责补测试，保留既有有效回归。
