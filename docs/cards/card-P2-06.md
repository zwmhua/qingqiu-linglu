## 2. 技能数据、生成与展示

定义 12 个初级技能。每项用稳定技能 ID、名称、说明、主动或被动、等级档、同系标识及参数表达。高级仅预留等级表达能力。技能说明沿用 §4.1 全部模板、反应伤害共用短句和展示顺序。百分比、倍率、次数、等级系数、除数、耗蓝均来自对应配置。基础参数按下表及 §3，数值加成和战斗触发由后卡接线。

| 技能 | 展示配置 |
| --- | --- |
| 暴击、连打、噬血 | +10% 暴击率和 2 倍伤害、45% 两击且每击减伤 25%、实际伤害的 25% 回复 |
| 还击、反弹 | 30% 且普通物理伤害的 50%、30% 且实际所受伤害的 25% |
| 巨力、硬甲、迅捷、回血 | 每级攻击 +0.4、每级防御 +0.6、速度 +10%、按真实等级除以 2 向下取整 |
| 雷击术、火球术、水箭术 | 三法术共用 §3.3 定稿参数，每次耗蓝 5，伤害随等级和双方灵力变化 |

| 物种 | 必带 | 随机池 |
| --- | --- | --- |
| 汀蛙 | 无 | 回血、迅捷、连打、噬血、水箭术 |
| 磐龟 | 硬甲 | 反弹、还击、回血、巨力 |
| 毛毛虫 | 无 | 暴击、连打、噬血、迅捷、巨力 |

普通随机数量 0/1/2 等概率，变异在该次结果上 +1。先放必带，再从去重的非必带池无放回抽。必带占技能格，总技能数上限 8。雷击术、火球术不在任一自然池，正式首获来源留后续打书。初始两只汀蛙各自抽一次。野怪确定物种和身份后抽一次；抓取按 ID 和原顺序继承完整列表，抓取和刷新均不重抽。可注入随机源，定向测试避免因新抽取改变已有抓取/战斗样本的随机顺序。

旧单字符串 `skill` 中的已知占位“露珠弹”不映射为水箭术或任何新 ID。旧档无此字段也照物种池补抽。遇到非已知的旧技能值，提示不兼容并保留原档。新档以 `skillIds` 为唯一技能来源，旧占位只用于识别历史输入。若既有无关引用确须保留，旧字段不得参与新展示、判定或迁移结果。

沿用资质技能页 4×3 的位置。前 8 格显示已拥有技能和空位，后 4 格为锁定。使用文字占位，暂不接入原画或新资源。点已拥有格，浮窗左侧用文字牌占图标位，右侧为技能名，下方为说明。主动技能显示耗蓝。当前物种必带加角标和“天生技能，无法被顶替”。点关闭按钮退出，切换宠物或离开资质技能页自动关闭。空格和锁定格不弹说明。遮罩拦截穿透，地图开面板继续沿用停步逻辑。

## 3. 点数与成长

| 对象 | 生成与升级口径 |
| --- | --- |
| 自然 0 级宝宝 | 五项随机分配共 50 点，每项至少 1，潜能 0 |
| 宝宝升级 | 每级五项各 +1，另 +5 到可手分潜能 |
| 新野生宠及初始汀蛙 | 生成时系统按真实等级分配全部 `50 + 10 × 等级` 点，潜能 0 |
| 野生宠后续升级 | 每级五项各 +1，另外 5 点用现有随机分配口径由系统投入五项，旧潜能余额原样保留 |
| 已有宠物 | 迁移保留五项和旧潜能。旧非宝宝和 `origin=initial` 开场汀蛙仍可手动花旧潜能，新升级按当前身份判断 |
| 人物 | 沿用原升级规则，每级五项各 +1、潜能 +5 |

计算按真实身份 `isBaby`，不能用等级 0 推断。宠物多升一级以上时，每级都满足 `五项总额 + 未分配潜能 = 50 + 10 × 真实等级`。复用现有经验阈值、胜利参与者口径及补满逻辑，新增随机投入只作用于本次新获得的点。升级更新派生属性，迁移不因技能重算为带技能加成的面板。自然生成复用 `generateBaseStats` 当前分配算法，避免重新洗点。

## 4. 存档迁移与失败重试

1. **按原版校验。** 当前正式版本是 v3，新版预计 v4，开工核对实际最新版本。显式区分 v1/v2 和 v3 的面板与 roster 规则。v1 缺失的宠物经验、潜能仍按现有读链补 0，v1/v2 临时面板按原规则验后沿用既有归一化，v3 按正式派生值和原名单规则验。保留现有等级、经验、五项、潜能、资质、成长、身份、ID、出战选择与抓取编号。旧档缺抓取编号时沿用现有推导，不重建个体。
2. **保留原始备份。** 正式主键仍用 `qingqiu-linglu:test-progress`。备份键采用 `qingqiu-linglu:test-progress:backup:v<旧版本>`。备份是该次原始字符串，内容完全相同的已有备份可复用。若同版本备份存在但不同，提示冲突，保留两份原样并暂停迁移，交华周决定如何保存两份。禁止用旧备份覆盖当前档案。
3. **生成一次并写入。** 完成原版校验及备份后，为每只旧宠按当前物种和变异身份补抽一组。校验新快照全部字段。新版 `skillIds` 须为列表，ID 已定义、无重复、最多 8，含当前物种全部必带；自然池仅约束生成，不能当作已拥有技能的存档白名单。校验失败不改主档。主档写入成功后才建立可玩的会话并展示技能，刷新读取既存列表。
4. **明确失败边界。** 读取、解析、备份读写、旧档或候选校验、写入失败均锁住正式进度和地图功能并提示原因，不能回退成新档。对可重试的存储故障提供「重试读取/迁移」入口。若已经构成完整候选，同实例的写入重试复用候选字节，提交前核对当前主档仍是当时读取的原始值。主档已变则提示重新加载。页面重载后允许对尚未提交的旧档重新构造候选，已成功的新版不再抽取。
5. **兼容与重置。** 未知版本、未知技能或会在当前格式写回时丢失的未知业务字段，提示不兼容、保留主档。原始备份保留完整 JSON。已知旧占位可从新版业务字段移出。开发测试重置沿用现有开关，只清本游戏的当前主档，不清备份。备份手动恢复或清除入口留待另行授权。

这条顺序保证老档在玩家看到新技能之前已有对应的原始副本，失败时仍能回到可核对的输入。P2-04 的战斗结算将完整新版快照一次写回，保留原有同候选重试语义。

## 6. 测试与一次试玩验收

- **技能**　确定性覆盖三个物种、随机数区间端点、普通 0/1/2、变异 +1、无放回、必带和上限。证明两个书本专属技能不会自然抽出，敌方生成列表与携带、保存、刷新后的列表一致。校验 12 条文案从配置取值，必带说明随物种判断。
- **点数**　用固定随机输入验证宝宝基础 50 且每项≥1。宝宝与野生各实际升一级，多级和封顶覆盖。新野生没有待分点，旧野生和初始汀蛙原潜能保留且仍能花。人物原规则、宠物总额、派生面板及读回均有断言。
- **完整存档路径**　使用真实版本结构的 v1、v2、v3 样本，分别验证原规则读取、原始备份、写新版后才能进游戏、两次刷新不重抽、原资料无意外变化。至少包含只有一只宠或仍有旧潜能的合法 v3、带抓取 ID 的旧档。注入备份读写、新主档写入失败、冲突备份、坏档、未知版本及技能。验证同实例重试候选字节相同，失败无读档回退或数据清除，开发重置保留备份。
- **浏览器**　执行窗口用 ego-browser 提供实际预览 URL 及明确隔离的试玩资料准备步骤。准备一份含磐龟与旧潜能的有效旧档、分别接近升级的宝宝和野生宠、固定抓取样本。可用已存在的开发样本机制或受控浏览器夹具，注明字段、等级、随机输入和预期。预览准备不得自动替换玩家正式档。
