## 2. 范围与交付

主线已有暗雷、技能、掉落及养成的独立定向测试，未有共用离线模拟入口。本卡按定稿新增一个入口，沿用现有 Node 环境、测试加载方式及规则函数。报告存 `docs/p2-14-balance-report.md`。华周能按报告重走路线、看到时间和收益，逐项决定 P2-15 是否采纳建议。

| 验证对象 | 报告要交的结果 |
| --- | --- |
| 暗雷与成长 | 从现有 `EncounterDistance` 得到触发距离均值、P50、P90，注明是否含保护距离。验证保护内与镜头单独移动均为零触发。统计敌群数量、宝宝出现率和宝宝中变异比率。分物种记录自然普通宝宝、变异宝宝和非宝宝野生的资质、成长与技能数，核对宝宝／野生升级后的点数口径。 |
| 战斗与技能 | 用 `Battle` 和现有属性派生做同资料的无技能／单技能对照，覆盖 12 个技能及代表性组合（如连打＋暴击、噬血遇反弹／还击）。按固定等级、敌人、技能和指令记录胜负、回合数、剩余气血／法力和相应技能效果。触发率写清分母，例如符合条件的攻击次数。 |
| 战胜掉落 | 用 `rollDrops` 分别抽正式与测试两组，每组至少 10,000 个合资格胜场，给三类命中数、比例及 12 本书的分布。正式 8%／3%／1%，测试 50%／30%／10%，10,000 次理论期望分别为 800／300／100 和 5,000／3,000／1,000。抓胜归入胜利，败逃沿用已有定向测试核对资格。 |
| 打书、还童、合宠 | 调用现有纯逻辑。打书按槽位分档报告新增／顶替，含天生技能可顶替的现行规则。两种还童分别观察生成身份、资质、成长和技能数。合宠分同种／异种、普通／变异，记录物种去向、子代资质与成长相对父母均值的变化，以及继承技能数。每组概率与成长分布至少 10,000 个样本，写明父宠或输入详情。 |

概率和成长的各相关分组至少 10,000 样本。模拟统一记录 SHA、Node 版本、运行命令、固定种子、各组样本量和分母。用同一组输入复跑应得到相同的统计数据。概率端点及组合边界查现有定向用例，新增小样本测试验证固定种子复现与统计口径。频数与理论期望允许存在抽样差，报告写差值和样本量。比较结论以实际执行的代码和输入为准。

## 3. 真实试玩验收

执行窗口先用本机 ego-browser 实点。复用已有固定样本或隔离浏览器中的临时资料，记录样本的等级、物种、技能、出战及模式。弱／中／强三个样本、1／2／3 怪、手动／自动都须覆盖，可在少量代表性场次交叉取样。用正式掉率入口实走至少一段连续自然遇敌，固定样本可用来补齐怪数与战斗对照。

| 华周怎么点 | 应看到什么 |
| --- | --- |
| 从标题进入城镇，打开报告所列的验收样本，点「出城」，按路线走到遇敌 | 能从普通入口开打；报告标出路线、自然／固定遇敌及样本差异。 |
| 手动打一场，再开自动连续打 | 结算和掉落提示可以核对。报告逐段记录行走、战斗、菜单耗时、胜败、掉落实收及明显费点的操作。 |
| 打开预备好双亲的合宠样本，完成合成，再回城 | 能看见两旧换一新的结果。报告注明双亲为预置资料，合宠操作耗时和练出两只合格宠所需时间分别记录。 |

实测每分钟胜场用实际胜场除以同段总用时，包含走路、战斗和菜单。若据此估计正式掉落等待时间，列为理论外推并给公式；同时列本次实收。未实际覆盖的样本或平台写 `NOT_TESTED`，注明原因。报告末列可能影响体验的问题、证据、改动的好处与代价、建议保留或调整的配置项，待华周拍板后才进入 P2-15。
