## 需求边界与拆分顺序

城里从背包「仓库」页签进仓库，点「背包」返回，右上可关闭。野外照常开背包，仓库页签提示「回城后可使用仓库」。战斗背包沿用只读。仓库固定用定稿青绿底图，左「仓库 1」、右「我的背包」，各显示 5 列 × 5 行并独立向下滚动。仓库 1 是标题。沿用角色背包、图标和说明气泡。仓库气泡只提供对应的「存入」或「取出」，背包页继续承接道具使用。

两侧各按 `itemId` 合堆，数量沿用现行规则。W2 支持整堆存入和取出，单件堆也适用。W3 为多件堆增加数量选择，范围为 1 至当前可用量，默认全部，确认后刷新双方，取消零写入。两颗整理按钮各按现有道具目录顺序整理自己一侧。整理只改变本次打开仓库期间的显示顺序，物品种类、数量和存档格式均不受整理影响。统一玩家存档负责库存迁移与刷新读回。

排除总格数上限、`stackLimit=99` 行为、多仓库、扩容、付费、分页、出售、丢弃、批量使用、装备穿脱、属性加成、新道具、排行榜、联网和广告。打书、还童、合宠规则沿用基线。

## W2｜原子存取、旧档迁移与回读 `qa`

- **接收窗口**　新 Codex 执行窗口，从包含已验收 W1 的干净基线开工。
- **推荐模型与档位**　`gpt-6-astra` / High。高风险存档迁移和双侧事务，错误会造成玩家库存丢失或复制。
- **完整卡片**　本节与上方需求边界、下方共同交付和停止条件一同转发。
- **补充提示词**　开工先核对实际存档版本和逐文件行数，超限先拆卡。实现整堆存入与取出，保存成功再一起更新两侧。按实际版本升一版，以原始备份保留旧档，验证合成宠、序号与已有库存。用多件堆、旧档、即时双击和故障写入样本实测。

**开工复估与超限拆卡**　动代码前按文件列出迁移、保存事务、转移规则、界面接线和回归测试的预计新增与删除，按根 `AGENTS.md` 核算。预估或实际超限按 X2 停止，先拆成 W2A「旧档迁移与回读」和 W2B「整堆存取与保存事务」。两张均标 `qa`，分别列估算和验收，报华周确认后再继续。W2A 可从 W1 的入口用旧档核对空仓、原始备份及人物、宠物和背包读回。W2B 依赖 W2A 验收，交付整堆存取试玩。W3 以 W2B 为前置。失败测试和有效断言保留，行数通过缩小单卡范围解决。

**目标与改动范围**　在 `assets/battle/logic/` 的 `inventory.ts`、`session-progress.ts` 和 `local-progress.ts` 里复用道具校验、共享会话及读写快照。规则层按方向、`itemId` 和数量计算两侧候选，执行时再核对城镇许可、当前库存、来源和数量，一次动作只允许提交一次。目标已有同 ID 就合堆，超出现有安全整数边界时整笔拒绝。候选含两侧数量和完整进度，复用 `progressIO` 一次写主档，写成后再一起更新内存。失败沿用现有提示与重试习惯，保持两侧和原档，重新操作要按当前量校验。`BattleView.ts` 只传入界面与城野状态、调用规则层、刷新结果。城里从气泡直接「整堆存入」或「整堆取出」，转移来源堆的全部数量。数量选择归 W3，仓库页的道具操作限存入和取出。

Codex 开工核对所选基线的实际存档版本及兼容判断，再升至下一版。迁移前保留可恢复的原始旧档备份，旧档迁移出的仓库为空，背包、人物、宠物、出战、经验及抓取、合成、结算序号原样保留，继续兼容基线支持的融合宠和超过八个合法技能。复用原档备份与失败重试链。普通背包使用、打书、还童、合宠、养成和战后结算继续经过统一存档，写入后仓库应仍可完整读回。

**逻辑与接线测试**　优先扩展 `tests/inventory.test.mjs`、`tests/session-progress.test.mjs`、`tests/progress-migration.test.mjs`、`tests/town-progress-integration.test.mjs`，按需要同步既有版本断言。规则层覆盖双向、部分与全部、同 ID 合堆及大于 99、按 ID 守恒（源扣量等于目标增量）、零／负数／小数／非法 ID／不足／溢出。接线覆盖单件堆与多件堆均能直接整堆存取、连续点击与过期操作、野外及待保存阻断。模拟存储写失败，断言两侧内存和主档原样、无成功反馈，重试最多落一次。以开工确认的实际版本为紧邻旧档，覆盖受支持版本的迁移、原始备份字节一致、保值、失败后重读和新档往返。以已有仓库物品为前置回归普通背包使用、打书、两种还童露、合宠和战后保存，再重读确认仓库未被覆盖。

**试玩验收**　用非空背包旧档进城，看仓库为空、背包和宠物原样。将单件技能书存入仓库，刷新核对，取回后关闭重开核对。再用背包 7、仓库 2 件同种道具的隔离样本，点整堆存入，核对背包该堆消失、仓库为 9。刷新后点整堆取出，核对背包为 9、仓库该堆消失。两步都用连续点击样本核对只提交一次。模拟写失败时两侧数量原样且无成功提示，恢复存储后再尝试一次并刷新。回到「背包」，在隔离档实点使用、打书和还童，确认扣量来自背包。野外从仓库页签只看到回城提示。

**同 SHA 静态 QA 重点**　旧档兼容及融合宠保值；双侧先保存后生效、重复与失败路径；其他快照写入保留仓库字段。执行窗口负责运行上述负例。

## 共同交付和停止条件

- 逐卡在干净独立工作树开发，保留原工作区、分支及美术。定稿后按项目规则在 `docs/cards/` 分别留档。交起始和最终完整 SHA、本地提交、业务和测试实际增删、定向与全量 `node:test`、限定严格 TypeScript 检查、ego-browser 实点结果和截图。给出可重开的试玩命令／入口及本卡需要的微信包与扫码步骤，未执行的项按 `NOT_TESTED` 记录。QA 结论只绑定所审完整 SHA，静态审查只读 diff。真机由华周验收，最终 STATUS、推送与合并由华周决定。
- **X1**　读不到必需的规则、源码或局部改动归属不清，基线欠背包或炼妖合并，工作树有未知改动，或者 W1 找不到原 PNG。保留现场，报告具体文件、分支和 SHA，再等华周裁定。每张卡开始前也核对上一张的验收 SHA。
- **X2**　逐文件复估或实际 diff 超项目阈值，需改白名单外路径、引入依赖或新增玩法规则，出现数据损坏、迁移备份冲突或权限风险。停在原数据和测试上，附证据与可缩减的范围。测试、浏览器或构建失败先在本卡范围定位并重试，仍无法验证时报告实际失败项，等待华周决定是否进入下一张。第三次回修前重新三问。
- 试玩和取证完成后，正常保存退出本卡启动的 Creator、预览服务／代理及 ego-browser；共用 ego-browser 时只关闭本卡工作区。保留华周正在用的工程和无关软件。只做本地提交，候选交华周试玩。
