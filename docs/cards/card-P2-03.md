## 2. 玩法与接线

| 项目 | 规则 |
| --- | --- |
| 地图 | 暂称「野外」。使用仓库现有 `assets/outskirts/textures/map_qingqiu_outskirts_wide.jpg`，原图 3344×941，保留 UUID 和 `.meta`。通过既有 `outskirts` Bundle 按需加载。 |
| 世界尺寸 | 视口 1334×750。野外等比按高度 750 铺设，世界宽度由 `3344 × 750 / 941` 得到，约 2665.25。坐标、尺寸和比例集中配置，图不拉伸，也不压成一屏。 |
| 可走区 | 结合画面标定出生点和一块或多块凸区。桥、河水和溪对岸均为装饰，不可走。出生点和用于验收的路线必须实际点过。 |
| 直线移动 | 沿用 180 世界单位/秒、单一有效触点、新目标覆盖旧目标、到点停止。不可达时清目标、提示「不能直达」。无寻路、绕行、摇杆或滑墙。 |
| 镜头 | 以世界位置跟随，按地图边界夹取视口原点。地图覆盖的轴到边不露底色，短轴居中固定。地图和人物同层移动，HUD 与面板固定。 |
| 点地坐标 | 先用 Cocos 的 UI 坐标换到视口局部，再加当前镜头偏移得到世界位置。缩放、黑边、镜头夹边使用同一套转换。只按人物脚底世界坐标判断路径和距离，镜头偏移与立绘起伏不算位移。 |
| 暂停与触摸 | 开面板、切后台、失焦、取消触摸、禁用或切换地图即停步清目标。恢复后需要重新点地。UI 与加载状态阻断地图触摸，沿用 B 的禁用和多触点回归。 |
| 功能入口 | 城里启用「出城」，野外对应「回城」。人物与宠物在两处都可使用，背包与合宠继续显示未开放。 |

整条移动线段必须被可走区域并集覆盖。可复用现有凸区半平面判定，求线段在各凸区内覆盖的区间并按配置容差合并。接壤或重叠的区域可以直达，河水造成的真实断口必须拒绝。相比只看起终点，这能防止两端看似合法时角色穿河。

### 往返与同档

- 复用 B 的 `TownView.ts` 与地图预览分支，按区域配置切换场景内容。保留同一个 `SessionProgress` 和已有面板事务入口。回城落在城里出生点，出城落在野外配置的出生点，两处均清目标。城镇保持单屏。
- 切换中只接受一次有效操作。加载失败时保留来源地图和资料，解除切换锁，可重试。切换、重试、打开面板和镜头复位不得新建 Battle、重新初始化宠物、发奖励或额外写档。旧异步回调不得重挂已离开的地图或重复创建节点。
- 在野外按原规则加点或放生时，仍由 A 的事务提交真实进度。往返仅改变会话位置和区域，位置不入档。刷新预览从已有快照回城。保留 B 的读档失败、保存失败、出战宠保护。
- 旧正式入口保持，预览沿用 `townPreview=1`。本卡的野外可以走动和回城，任何距离都不会开战。

### 首区怪物池配置

在区域配置中关联既有遭遇规则，供后续卡接入。汀蛙、磐龟、毛毛虫等权，野生等级 1～5 等权。每场 1/2/3 只权重 50%/35%/15%，宝宝 5%、真实等级 0，变异 25%。复用 `wild-encounter.ts`、`battle-rules.ts`、`baby.ts`、`mutation.ts` 的现有来源，按需导出或注入，不另写一套同值表。野外池的配置不会改变普通战斗入口的生成结果。遇怪距离累计、抽取、自动战斗、战斗返回点和奖励结算留后续卡。

### 包体

`outskirts` 已在主线声明为独立分包，B 的构建记录也已单列它。沿用该归属，保留原图和 UUID，脚本留 battle，Boot 不静态引用野外资源。设计表中的 battle 包体估算按实际产物校正，不搬图或增加分包。交付时按同口径记录主包、battle、town、outskirts、总包及相对起始提交的增量，核对野外图仅在 outskirts。主包沿用构建文档的 3.5 MB 停止线，未构建写未测量。

## 4. 验证与交付

使用现有 `node:test`、限定 `tsc` 和 Creator 预览检查，沿用已有测试方式。新增断言至少覆盖：

- 镜头左右端夹取、短轴居中，滚屏后的同一点击映射到正确世界位置。
- 同一凸区可达，相接或重叠的多块可达，两个合法端点之间有河沟时拒绝，区外点击清目标。
- 镜头补位、传送和复位不改变实际步行距离。面板、后台、禁用和切图清目标，第二触点不能覆盖第一触点。
- 正常往返和失败后重试不替换同一份进度、不额外写档，首区池与旧规则一致，普通战斗入口仍可用。

开发先用本机浏览器实际操作，报告提供完整预览 URL、普通启动 URL、可走区验收点击位置和同档样本。华周最终试玩按下列步骤：

1. 打开城镇预览，点「出城」。走到宽图左右可达尽头，镜头跟随且两侧不露底色，按钮不漂移。换一个浏览器宽度再点地，确认仍落到点中的地面。
2. 在本岸沿相连地面点远处可到。点桥、河水、对岸均不可达，并提示「不能直达」。若本岸地形有两个合法端点之间隔水的路线，在预览中一起验证。没有这条路线时，用固定几何样本验证整段判定，保留正式图的实际可走区。
3. 行走中开人物/宠物面板，角色立刻停住。点面板不穿透，关掉面板、切后台再回来都不会续走。停留或走动均不出怪。
4. 用验收样本确认一次人物或宠物加点，回城后查看同一资料，刷新仍保存成功结果并回城。往返不重抽宠物、不变更出战标、不发经验。
5. 开发演示加载失败后重试，来源地图与资料保持，成功后只进入一次。普通启动仍进入原战斗。

微信模拟器和真机有可用预览入口时，按实际操作记录滚屏点击、边缘、清晰度和往返。若当前构建的 PREVIEW 参数不可用，分别标 `NOT_TESTED` 并写明原因，保留到 P2-05 平台回归。可预览但没打开，或无法预览，也写 `NOT_TESTED`。QA 只读最终提交的 diff，重点审坐标、断口、加载重试和同档。运行测试与浏览器试玩由开发完成。
