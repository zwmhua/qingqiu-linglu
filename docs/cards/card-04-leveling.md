# 青丘灵录｜卡 04 总规则：经验、人物与召唤兽升级成长

**状态：策划终稿 v1.0｜规则全部拍板｜尚未授权开发。**  
**阶段：** 第一阶段 Web 原型（Cocos Creator 3.8.8，横屏 1334×750）。  
**前置：** 华周已确认 03a、03b 全部试玩通过。  
**分卡与顺序：** 04a 经验与人物升级 → 04b 人物面板与加点 → 04c 召唤兽升级与潜能。每张须先由华周试玩通过，再由华周单独授权下一张；04c 必须等 04b 通过。  
**目标：** 战斗胜利给经验，人物和召唤兽能从当前等级成长到 20 级，并通过可确认的潜能加点形成基础养成闭环。

## 一、对象与统一升级规则

- 唯一人物为「撷灵客」，人族均衡型；抓回来的野怪就是召唤兽，不另建一套宠物身份。
- 人物与召唤兽共享 **0～20 级**升级规则与经验表。真实 0 级仍显示 0 级，参与战斗时使用 `effectiveLevel=max(1,level)`；20 级封顶。
- **每升 1 级：五项自动各 +1（合计 +5），另将 5 点加入未分配潜能。** 五项固定为体质、法力、力量、耐力、敏捷。未分配潜能允许累计；升级自动点立即生效，手动点仅在确认后生效。
- 对人物与每只召唤兽，始终满足：**五项已分配数值之和 + 剩余潜能 = 50 + 10 × 真实等级**。
- 已确认的加点保留，本阶段不做洗点；五项数值和潜能不得为负、不得突破可分配额度。
- 经验、升级与潜能数字全部从配置或统一规则计算；人物与召唤兽不各造一套经验算法。

## 二、人物 0 级初始值与人族系数

撷灵客初始真实 **0 级**，五项各 **10**、合计 50、潜能 0、当前等级经验 0。显示仍为 0 级；有效战斗等级为 1，但**不另造 0 级战斗属性底值**。使用五项全量直接换算，不再沿用旧卡 01 固定 `58/10/13/9`。

**已拍板人物换算（只用于人物，不用于召唤兽）：**

| 五项每 +1 | 面板增量 |
|---|---|
| 体质 | 气血 +5、速度 +0.1、灵力 +0.3 |
| 法力 | 法力上限 +3、灵力 +0.7 |
| 力量 | 伤害 +0.66、速度 +0.1、灵力 +0.4 |
| 耐力 | 防御 +1.5、速度 +0.1、灵力 +0.2 |
| 敏捷 | 速度 +0.7、躲避 +1 |

设体质 `C`、法力 `M`、力量 `S`、耐力 `E`、敏捷 `A`：

- 气血上限 `5C`；法力上限 `3M`；伤害 `0.66S`；防御 `1.5E`；
- 速度 `0.1C + 0.1S + 0.1E + 0.7A`；躲避 `A`；
- 灵力 `0.3C + 0.7M + 0.4S + 0.2E`。

**所有换算中间保留小数，每个最终面板值统一四舍五入一次。**

| 0 级人物面板字段 | 计算 | 初始显示 |
|---|---|---|
| 等级、名称 | 真实等级／固定名 | **0／撷灵客** |
| 当前／最大气血 | 10×5 | **50/50** |
| 当前／最大法力 | 10×3 | **30/30** |
| 伤害 | 10×0.66＝6.6 | **7** |
| 防御 | 10×1.5 | **15** |
| 速度 | 10×0.1×3＋10×0.7 | **10** |
| 躲避 | 10×1 | **10** |
| 灵力 | 10×(0.3+0.7+0.4+0.2) | **16** |
| 升级经验 | 当前/升到下一级所需 | **0/10** |

0→1 升级、尚未手动加点时，五项各 11、潜能 5；最大气血 55、最大法力 33、伤害 7、防御 17、速度 11、躲避 11、灵力 18。

**平衡提醒：** 0 级人物伤害为 7，低于卡 01 旧版 10；既有胜率数据不能拿来当本卡通过的依据，由华周试玩判断是否仍好玩，不擅改系数。

## 四、每场战斗经验结算

战斗**开始时**锁定敌方初始名单，每只敌人的经验为：

`enemyExp = 8 + 2 × max(1, enemy.level)`

**整场胜利经验 = Σ 每只初始敌人经验**。0 级宝宝按有效 1 级贡献 10；1～5 级普通野怪分别贡献 10/12/14/16/18。数量与等级按卡 03 现行规则生成，不变。

- **胜利**：发放该场全额经验；**失败**：所有人和召唤兽获得 0。
- 已抓走的敌人仍计入本场胜利经验，抓取成功不额外加经验；不按最终剩余敌人数重新计算。
- **人物**只要整队最终胜利就得全额，即使人物本场倒地。
- **本场实际出战过的每只召唤兽**各得全额，倒地、途中换下仍算；重复召唤同一只不重复给；仅携带未出战的得 0。
- 新抓个体进入携带时**当级经验从 0 开始**；只有本场抓到后确实上阵，才有资格得到本场经验。
- 一场只有一次结算。胜利界面、重开战斗、刷新页面或重复触发事件不得重复发奖；各个体升级、剩余潜能与经验进度分别保存。
- **升级后**当前气血/法力补满新上限；**每场新战斗开始**按各自新的最大值满血满法。召唤兽暂未使用法力战斗机制，不因此新增法术或消耗。

## 五、初始召唤兽、抓取与成长

- **初始两只**均为汀蛙、普通野生、非宝宝、非变异；**每只独立等权随机 1～5 级**，可以碰巧同等级。各自按该等级既有规则生成六资质、成长、五项，且同一个体不因查看、战斗或刷新而重掷。
- 野生 N 级召唤兽生成时五项**已随机分配**，合计 `50+10N`、每项至少 1，进入携带时潜能 **0**；抓回来的怪物沿用其场上等级和个体资料，**不重新随机一只**。
- 0 级宝宝五项合计 50、初始潜能 0；首次 0→1 **五项各 +1、潜能 +5**，此时已分配五项合计 55，尚有潜能 5；不额外随机自动发放 10 点。
- 每次后续升级均沿用统一规则；六资质、物种成长、宝宝/变异身份不因升级或加点而改变。

## 六、召唤兽临时战斗面板（系数不变，适用至 20 级）

设 `d=max(1,真实等级)-1`。敌方及己方召唤兽沿用卡 03 下表；初始两只汀蛙**不再特殊保留** `38/11/10/10`，一律依各自等级走汀蛙公式。

| 物种 | 最大气血 | 攻击 | 防御 | 速度 |
|---|---|---|---|---|
| 汀蛙 | `33+4d` | `10+floor(d/2)` | `9+floor(d/2)` | `9+floor(d/2)` |
| 磐龟 | `45+6d` | `9+floor(d/2)` | `13+d` | `7+floor(d/2)` |
| 毛毛虫 | `26+3d` | `14+floor(d/2)` | `7+floor(d/2)` | `10+floor(d/2)` |

只把适用等级延伸到 20，不改任何系数。召唤兽五项加点、六资质和成长值**暂不影响**上述临时四维，仍可在详情查看；不在本阶段偷偷做正式换算。同种同级但五项加点不同，临时战斗面板可能相同，这属于第一阶段已接受的原型边界。

## 七、面板、加点与确认

**人物面板先做文字版，左右分栏，字段不能缺：**

| 左栏（战斗信息） | 右栏（五项与操作） |
|---|---|
| 等级、名称：撷灵客 | 体质 ＋/－ |
| 当前/最大气血 | 法力 ＋/－ |
| 当前/最大法力 | 力量 ＋/－ |
| 伤害、防御、速度 | 耐力 ＋/－ |
| 躲避、灵力 | 敏捷 ＋/－ |
| 升级经验：当前/本级所需 | 剩余潜能、确认、取消 |

- 点击 `＋` 扣除**预览中的可用潜能**，临时增加该项；点击 `－` 仅能撤销本次未确认分配，不得撤回自动增长或历史已确认点数。
- 左栏同步预览**人物**经人族系数换算的结果；点击「确认」才成为有效值并保存；点击「取消」或直接关闭，预览全部放弃。
- 允许只分配部分潜能，剩余潜能继续累积；战斗进行中不能更改加点。下一场战斗只读已确认属性，预览值绝不进入战斗。
- **召唤兽详情**保留原有物种、等级、身份、六资质、成长及召唤功能，增加升级经验、五项、剩余潜能以及同一套 `＋/－/确认/取消`。其预览显示五项和潜能变化，临时战斗四维不因加点变化。
- 不放称谓、人气、门派、帮贡、愤怒、活力、法伤、法防或无关页签。正式 UI 皮肤后续再换。

## 八、浏览器本地测试进度与重置

第一阶段使用浏览器**本地测试进度**，建议具体采用 `localStorage`（单个本游戏命名空间/键、版本号，避免破坏其他网站数据）；不是正式存档系统、账号同步或云数据。

- 保存人物和召唤兽各自的等级、当前经验、五项、剩余潜能与已确认加点结果。
- 为保证同一只召唤兽始终是同一只，同时保存个体 ID、物种、六资质、成长、宝宝/变异身份、携带名单及当前出战选择；不得在刷新时重新随机。
- 不保存战斗中敌方临时状态、行动指令与未确认预览；刷新后可重新进入一场完整战斗，不应重复结算上一场。
- 提供**测试用「重置」按钮**，点击须二次确认：确认后仅清除本游戏的测试进度，恢复 0 级人物（五项各 10、经验 0、潜能 0）和两只**重新独立随机**的 1～5 级普通汀蛙；取消不改变任何数据。重置不会删除其他网站/其他功能的存储记录。
- 本地数据缺失时正常初始化；数据损坏或版本不兼容时不能误读成已验证进度，也不得误删无关数据。给出明确提示或安全重置路径。

本地持久化读写及清除是 `qa` 风险；04a/04b/04c 均涉及读写，三张分卡均标 `qa`。

## 九、现行战斗出手规则（记录在总卡，**不在卡 04 开发**）

以下是规则约束/后续独立修补依据，**不作为 04a、04b、04c 的新增实现或验收范围**：

- 每回合**先选指令，再按速度统一结算**；速度高者先出手；同速时我方先于敌方，同边按站位编号由小到大。
- 同一回合，**我方出战位的召唤兽最多出手一次**。
- 人物在本回合召唤或换上新召唤兽后，**新上场召唤兽本回合不能出手**。
- 被换下的召唤兽若尚未出手，**本回合也不再出手**。

本卡不得借此扩大战斗回合重构；若当前实现与规则冲突，另按独立小修补处理。
