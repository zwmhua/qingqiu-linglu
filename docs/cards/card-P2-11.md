## 2. 玩家流程和概率

在城里或野外打开背包，点一本技能书，选择携带宠（包括当前出战宠），点「打书」。弹出确认，列出书名、宠物、当前技能数、新增概率、顶替概率和「消耗 1 本」。有顶替概率时说明会随机替换一个非必带技能，玩家确认后才抽取。取消返回背包。战斗中保持原背包只读。

| 当前技能数（含必带） | 新增 | 顶替 |
| --- | ---: | ---: |
| 0～1 | 100% | 0% |
| 2 | 60% | 40% |
| 3 | 30% | 70% |
| 4～8 | 0% | 100% |

- 只接受 P2-10 目录内的 `book:<skillId>`，当前库存至少 1，本次确认的宠物仍在携带中。技能已学、缺书、宠物失效或战斗中均提示原因。在可以触发顶替的档位，若替换候选为空，直接提示「只有必带技能，无法顶替」。这些拒绝和取消均零扣书、零抽样、零写入。
- 新增时技能放在首个空格。顶替从同一宠物当前的非必带项中等概率抽一个，填回被替换的格子。其余技能保持原顺序。磐龟天生的硬甲受保护；汀蛙学来的硬甲正常进入替换候选。必带占 8 格中的一格，4～8 技能只替换。
- 用纯 TypeScript 配置保存上表，概率判断用 `roll < rate`，抽样可注入。只有两种结果都可能时才抽分支，确定顶替时只抽替换位置。
- 成功后背包减少一本，结果显示「新增 X」或「X 替换 Y」。原宠 ID、等级、经验、五项、潜能、资质、成长、宝宝/变异身份及出战选择照原值。属性页和下场战斗由原派生公式读取最新技能。
- 若被替换的正是这只宠记忆中的自动灵术，保存成功后清除该条已失效记忆，下场回到 P2-09 的默认选技。其他自动记忆仍按原规则。还童露、合宠、新技能槽和高级书由各自的后续需求承接。

## 3. 保存与连点

确认时重新校验上下文、道具库存和当前技能集合，拦截同一确认的重复提交。基于真实当前值构造新技能、减一本后的库存与完整 v5 候选，复用现有 `progressSnapshot` 和主档写入入口。技能与库存只写一次，写成功后才发布到内存和 UI。能影响显示或战斗的派生数值按现有公式重算，快照继续保存基础值。

写失败明确提示，保留原书、原宠、自动记录、出战选择和原主档，结束本次确认。再次尝试时按当前库存和宠物技能重新确认，只有实际保存成功的结果才显示。结算 ID、载入版本和原主键沿用 P2-10 的 v5。

## 5. 测试与固定样本试玩

- **纯逻辑**　覆盖 0／1／2／3／4／8 档，重点测 0.6、0.3 阈值两侧及相等。用固定随机值使每一个非必带候选都能被选到。用人工候选集合测试空替换池，不改真实物种配置。验证重复书、缺书、非法道具、取消和战斗中不抽、不扣。
- **进度与回放**　存储抛错时快照字节、书量、宠物与出战选择均保持。成功一次写入，重复回调和双击只生效一次。刷新后技能与余量一致。用被顶替的已记忆灵术验证保存成功才使该记忆失效，下场自动能正常执行。
- **本机 ego-browser**　复用明确选择的验收样本与现有 v5 背包路径。预置固定宠物、书与可控随机输入，实际操作走正常打书入口，报告实际可打开地址和步骤。正式/测试掉率开关只负责掉率。

| 样本与操作 | 应看到 |
| --- | --- |
| 城里给 1 技能的当前出战汀蛙用雷击术书，先取消再确认 | 取消书与宠保持。确认后「新增雷击术」，减 1 本；再次选择同一本有重复提示，余量保持。资质技能页可看到该技能，下一场可施放。 |
| 野外给 2／3 技能的固定宠分别用书 | 确认框显示对应 60%/40% 或 30%/70%，用固定值分别演示新增与顶替。 |
| 给 4 技能磐龟用书，再用 8 格样本 | 固定顶替一项非必带；磐龟硬甲仍在，技能数分别保持 4 和 8。另以普通宠的后天硬甲作可被替换对照。 |
| 战斗中打开背包；另在地图注入一次写失败后再成功确认 | 战斗只读。写失败有提示，余量和技能仍为旧值。成功后刷新，已扣数量和新技能一致。 |

## 6. 开工、独立 QA 与交接

开工时保护原工作区及素材，记录起始 SHA，把本卡原样落 `docs/cards/card-P2-11.md`。先补相关失败测试，再实现。运行定向和全量 `node:test`、覆盖实际传递依赖的限定严格 `tsc`、ego-browser 逐项试玩和现有 Web／微信构建。记录包体、测试结果、实际 URL、证据、业务与测试增删、最终 SHA。未实测项填 `NOT_TESTED`。只做本地提交交华周验收。

独立 QA 只读起始 SHA 到最终完整候选 SHA 的差异并绑定结论，使用 `PASS/FAIL/BLOCKED/NOT_TESTED`。重点核对：

1. 只按物种当前必带判保护；概率、技能数、重复书和空候选的边界都正确。
2. 扣书和技能同一份 v5 候选，只在写成功后发布。失败与连点不能产生半成功或重复消耗。
3. 城野许可、战斗只读、出战宠可打书、派生值重算与自动记忆失效仅在成功后发生。

**交接**　打书规则按 §5.2 实现，实际接线写 `ARCHITECTURE.md`，实测证据写 `docs/wechat-build.md`。华周试玩确认后补登 `STATUS.md`；下一张为 P2-12「普通与变异还童」。
