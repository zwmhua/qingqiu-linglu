## 目标（一句话）

玩家在原有抓宠流程中偶尔遇到 0 级「汀蛙宝宝」，抓住后能看到普通／宝宝／变异的区别，并在简单宠物详情里比较六项资质、五项基础属性与成长。

**为什么：** 02a 证明“能抓”；02b 才让玩家觉得“这只可能比上一只好”，从而愿意再抓一次。

## 范围与玩家能看到什么

1. **野外与宝宝：** 本卡仍只有汀蛙一个物种；野外汀蛙和汀蛙宝宝使用同一张汀蛙 SpriteFrame。每个遭遇单位按配置独立判断是否是宝宝；普通敌人显示「野外汀蛙」及既有等级，宝宝显示「汀蛙宝宝」且**等级为 0**。遭遇数量仍遵守卡 01 的 1 只 50%／2 只 35%／3 只 15%。宝宝遭遇概率固定为**每个遭遇单位独立 5%**。
   - **为什么：** 不增加新素材与新物种，也能产生“意外遇到稀有宝宝”的惊喜。
2. **宝宝更好：** 宝宝的六项资质各自在**普通对应资质区间的上半段**独立掷两次整数、平均并四舍五入；不是给既有野生数值直接乘倍率。各资质比普通野生个体**统计上更优**，但不保证每项都高于每一只普通野生个体。
   - **为什么：** 宝宝的六项资质整体更容易偏高，但高资质普通个体也有收藏价值，不必把宝宝设计成绝对碾压。
3. **等级 0 边界：** 宝宝进入携带列表后保留 `level=0`、`isBaby=true`。现有成长函数按 `(level - 1)` 计算，不可直接给等级 0 套用造成负成长；宝宝计算战斗属性时统一使用 `effectiveLevel = max(1, level)`，所以 0 级战斗属性暂按 1 级计算；不另造 0 级基础数值，也不提前做 0→1 升级。本卡只展示成长属性，不实现升级效果。
   - **为什么：** 把等级 0 真实存入数据，后续才能升级；但不能因此破坏卡 01 的伤害规则。
4. **六项资质：** 攻击、防御、体力、法力、速度、躲避。旧卡已给四项资质区间：攻击 **50–90**、防御 **55–95**、体力 **70–110**、速度 **50–90**；新增法力资质区间 **60–100**，躲避资质区间 **50–90**。普通资质沿用旧卡方法：每项在区间内**独立抽两次整数，取平均并四舍五入**。所有数值范围在 `assets/logic/` 配置中声明，不得写在界面组件里。
   - **为什么：** 两次取平均会让中等资质更常见、极端资质更少见；六项独立则有可比较的差异。
5. **成长：** 详情增加一个独立的「成长」字段。**每个物种分别在配置中定义 `growthMin`～`growthMax`**，普通个体在该物种区间内随机抽取，宝宝只从该区间的**上半段**抽取；同种不同个体可以有不同成长。以千分位整数均匀抽样、再除以 1000，保证**保留 3 位小数**并包含端点；上半段起点按千分位取区间中点向上取整。成长**不受变异倍率影响**；本卡只生成和显示，不参与任何战斗属性计算，也不实现升级或经验结算。**汀蛙成长范围已由华周确认：`growthMin=0.930`、`growthMax=0.970`；宝宝只在上半段 `0.950～0.970` 抽取。**
   - **为什么：** 成长跟物种走，不同怪物才有各自的强弱档次；同一种怪只在自己的小范围里浮动。以后给高级怪设定独立且合理错开的范围，就能避免新手怪的成长反过来高于高级怪。
6. **变异：** 沿用原卡：**只在抓取成功后**，按 **2.5%** 判定变异；变异时已定义的资质各乘 **1.18** 并封顶 **130**。扩展后的法力、躲避也一并加成：**六项资质逐项乘 1.18 → 四舍五入 → 封顶 130**。先按宝宝/普通规则掷六项资质，再对成功捕获后判定为变异者加成；**宝宝与变异可以同时存在**，且成长始终不乘倍率。抓取失败不判变异、不额外消耗随机抽取。
   - **为什么：** 变异应该是抓到后的少量惊喜，而不是每次失败都在暗地里抽一次奖。
7. **变异外观：** 仍复用同一张汀蛙图，通过 Sprite 调色显示明显不同的色调，并加「变异」文字标识。**受击时的红闪结束后，要恢复变异原色，不可重置为普通色**；头像、战场与详情展示保持一致。
   - **为什么：** 不增加贴图，也让玩家第一眼识别自己抓到了不同个体。
8. **简单宠物详情：** 在 02a 的携带列表中点击任意宠，打开轻量详情：名称、等级、普通/宝宝、普通/变异、六项资质、五项基础属性、成长；保持原有“召唤”入口可用，不新增背包整理、对比排行或技能养成。初始宠如无完整资质记录，需要提供与当前配置一致的确定性初始资料，不能在每次打开详情时重新掷属性。
   - **为什么：** 看清楚自己抓到了什么，是收集玩法的基本反馈；功能越少越容易判断是不是想抓下一只。
9. **新增五项基础属性（独立于六项资质）：** 分别为**体质、法力、力量、耐力、敏捷**。0 级汀蛙宝宝的五项合计 **50** 点；野生 **N** 级汀蛙的五项合计 **`50 + 10 × N`** 点（例如 1 级合计 60 点）。总点数在五项中**随机分配**，每个个体生成一次，抓取、召唤、跨战斗查看时保持原值；每项最低点数**待定**，建议至少 **1 点**（待华周拍板，未确认前不得当成正式分配规则）。五项基础属性只在宠物信息里显示，**本卡不把它们换算为气血、攻击、防御、速度等面板数值**，也不做升级加点与潜力点。初始两只宠物如缺乏对应资料，其初始五项分配方式须先核对现有配置，不得自行编造。
   - **为什么：** 五项是分配到个体身上的基础点数，六项资质表示它适合往哪方面成长；现在先让玩家看懂两者区别。升级如何加点、点数如何影响战斗，等后续卡再设计，避免连带改变已能玩的战斗。

## 不做

不做第二、第三种怪、地图、升级、经验表、技能书来源、法力/躲避的战斗效果、五项基础属性到面板数值的换算、升级加点、潜力点、成长公式实战生效、存档、放生、背包排序、多宠同时出战、另做一套战斗系统。保留卡 01、02a 的攻击、防御、抓取与召唤规则。

## 数值与逻辑要求

- 当前代码的纯战斗逻辑位于 `assets/scripts/Battle.ts`、配置位于 `assets/scripts/config.ts`；实现目标是将本卡新规则和所有本卡数值放在 **`assets/logic/`**，UI `BattleView.ts` 不抽概率、不生成资质。若 02a 已完成布局迁移，直接沿用。
- 已知配置：`baby.encounterRate=0.05`，`aptitude.attack=[50,90]`、`defense=[55,95]`、`stamina=[70,110]`、`speed=[50,90]`；`aptitude.mana=[60,100]`、`aptitude.dodge=[50,90]`；`species.<id>.growthMin`、`species.<id>.growthMax`（汀蛙已确认 `[0.930,0.970]`）、`growth.decimals=3`；`mutation.rate=0.025`、`mutation.multiplier=1.18`、`mutation.cap=130`。
- 宝宝概率应在**每个遇怪单位**创建时判断一次，不改变总遭遇数量；抓取概率仍是原卡 02 公式，不额外给宝宝暗加抓取率（如要更改，另列待定）。
- 普通野外个体目前按中等资质作为战斗参考；为保证宝宝更好，宝宝资质从各区间的中点至上限独立双骰（含端点），中点由配置区间计算，绝不另造加成率。
- 五项基础属性新增独立数据字段，与六项资质严格区分：`baseStats.constitution`（体质）、`mana`（法力）、`strength`（力量）、`endurance`（耐力）、`agility`（敏捷）。分配规则与总量在纯 TypeScript 逻辑及配置中定义；总量为宝宝 `50`、野生 N 级 `50 + 10 × N`，单项最低值暂以 `baseStats.minPerStat` 标记为待定（建议 `1`），未确认前不擅自写成运行时常量。
- 宠物资料一次生成、存于内存实例；关闭详情再打开、重新战斗或召唤，六项资质、五项基础属性、成长、等级、宝宝/变异标志不变。刷新页面清空。
- 现有受击 Tween 会将 Sprite 颜色恢复为白色；改动时须恢复为**该个体原本颜色**，否则变异色会在被打一次后消失。
- 原卡基于“所有敌人均为普通野外汀蛙”的胜率和场次模拟，加入宝宝、成长、携带上限后**不能直接当成新版本模拟结果**；后续有需要再重跑。

## 试玩标准（一次试玩会话内完成）

华周打开预览，至少抓到一只汀蛙，在携带列表打开详情，应一眼看到名称、等级、六项资质（含「躲避」）、五项基础属性（五项之和与等级对应）和保留 3 位小数的成长（落在该物种配置区间；宝宝只落在上半段），并能切回召唤；再进入战斗，资料应不发生变化。**罕见的 0 级宝宝和 2.5% 变异不要求华周靠随机连续刷几十场**。Codex 应提供只用于编辑器/测试的确定性样本展示方法（例如使用测试随机源在隔离测试模式展示一只宝宝和一只变异个体），不得影响正常战斗概率或发布版本。华周在同一次试玩中查看其颜色与标签即可。

如果测试展示做不到，应标「稀有外观：未验证」，而不是谎称已经亲眼看到变异。

## 逻辑测试（必须）

1. 遭遇数量和权重仍是 1～3 只的原规则；宝宝按已确认的独立概率产生并标记 `level=0`、`isBaby=true`。
2. 野外汀蛙与宝宝共用同一素材引用/物种标识，但名称及 `isBaby`、等级不同；抓到后不丢失类型。
3. 六项资质的取值全部落在确认的配置区间；两次独立整数抽样、四舍五入与随机源边界测试。
4. 宝宝六项资质只从普通区间上半段双骰、数值不越界；不强求宝宝所有数值必然大于所有普通个体。0 级计算战斗属性使用 `max(1, level)`，不得负成长。
5. 抓取成功后以 2.5% 判变异，失败时不判；普通和宝宝均可变异；六资质先抽样后乘 1.18、四舍五入、封顶 130；成长不受变异影响。
6. 对配置中任一物种的成长范围 `growthMin`～`growthMax`：普通个体抽样不得越界、宝宝只能落在该物种区间的上半段；验证上下端点可取、千分位精度与界面固定 3 位显示。变异不得改变成长，也不影响攻击、生命等战斗属性。
7. 同一只宠的资质、成长、类型、变异标记在打开/关闭详情、重开战斗、使用召唤后不变；刷新后恢复初始状态。
8. 战斗正常受击后，普通个体和变异个体均恢复各自原本色调；两者始终有可见区别。
9. **五项基础属性：** 宝宝 0 级五项总和始终为 50；野生 N 级总和始终为 `50 + 10 × N`；每项均为整数，且不低于**拍板后配置的单项下限**。大量不同随机输入下，五项都能获得随机点数，不得出现某项永远分不到点的偏向；生成后跨查看、抓取、召唤及重开战斗数值稳定；本卡不改变现有气血、攻击等面板属性。
10. 卡 01 的战斗测试和 02a 的抓取、容量、召唤测试继续通过。

## 已确认｜华周 2026-11-11 拍板

- **B1 宝宝出现率：** 每只遭遇汀蛙独立 5%，不改变 1～3 只的遭遇数量概率。
- **B2 宝宝六项资质：** 在每项普通区间**上半段**双骰并四舍五入；区间是攻击 **70–90**、防御 **75–95**、体力 **90–110**、法力 **80–100**、速度 **70–90**、躲避 **70–90**。这些上下界均由普通区间中点推得，不是额外数值设定。
- **B3 六项普通资质：** 攻击 **50–90**、防御 **55–95**、体力 **70–110**、法力 **60–100**、速度 **50–90**、躲避 **50–90**；每项独立双骰并四舍五入。
- **B4 成长规则：** 按物种分别配置 `growthMin`～`growthMax`；普通个体在全区间抽千分位，宝宝只在上半段抽千分位，显示 3 位；变异不加成，本卡不参与属性计算。**汀蛙区间已拍板为 0.930～0.970；宝宝区间为 0.950～0.970。**
- **B5 0 级宝宝：** 保留真实 `level=0`；仅在计算战斗属性时取 `max(1, level)`，暂按 1 级计算；0→1 升级留卡 04。
- **B6 变异：** 抓取成功后 2.5% 判定；先抽普通/宝宝资质，后六项乘 **1.18**，**四舍五入**，再封顶 **130**；宝宝可与变异叠加，变异成长不加成。变异颜色通过程序调色，复用同一图片。
- **B7 命名：** 普通敌方「野外汀蛙」、0 级宝宝「汀蛙宝宝」，两个类型共用同图；其余两种怪名仍待定、02b 不实现。
- **B8 五项基础属性：** 名称为体质、法力、力量、耐力、敏捷；宝宝 0 级合计 50 点，野生 N 级合计 `50 + 10 × N` 点，随机分配；本卡只生成并显示，暂不参与面板数值计算、升级加点或潜力点。**每项下限建议 1 点，待华周拍板。**

**本卡待定（需要华周拍板）：** 五项基础属性随机分配时，每项最低点数是否定为 **1 点**；当前只是建议，执行前需确认。初始两只宠物如无五项属性数据，初始分配方案亦需核对并明确。其他物种的成长范围留待对应物种设计时确定。

**其他后续待定：** 卡 04 的经验、升级与成长实战公式；其他两种怪的正式名称。Codex 不得提前编造。
