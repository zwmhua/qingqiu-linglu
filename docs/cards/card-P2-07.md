- **真实目标**　让巨力、硬甲、迅捷、回血真正作用于有该技能的召唤兽和敌方灵宠，且玩家看到的属性与战斗计算一致。

## 2. 规则与显示

定义 `L = 个体真实等级`。召唤兽的取整前基础值沿用现有面板公式，公式内部需要有效等级时继续用现有有效等级。因此 0 级宝宝可以沿用有效等级 1 计算基础属性，技能的等级加成仍用 0。敌方继续以 `wildCombat` 的现有基础结果作为输入，那套基础值本来就是整数。人物沿用原属性和排序逻辑。

| 技能（ID） | 定稿公式 | 显示与战斗 |
| --- | --- | --- |
| 巨力（`power`） | `Math.round(取整前基础攻击 + L × 0.4)` | 召唤兽「伤害」与该单位攻击计算共用结果 |
| 硬甲（`armor`） | `Math.round(取整前基础防御 + L × 0.6)` | 召唤兽防御与战斗物理防御共用结果。效果仅改变防御 |
| 迅捷（`swift`） | `Math.round(取整前基础速度 × 1.1)` | 用同一个最终整数做速度显示和战斗排序。整数相同继续走既有同速规则 |
| 回血（`regen`） | `min(floor(L / 2), 气血上限 − 当前气血)`，最低 0 | 回合开始时计算实际恢复，气血变化和正恢复量写战斗日志 |

倍率、每级加成、除数读取现有 `PET_SKILLS` 参数。前三项在基础公式结束后计算技能，加成所得的最后结果用 JavaScript `Math.round` 四舍五入一次，非负数的小数部分正好 0.5 时向上。无对应技能时按现有方式取整。基础伤害、物理减伤、出手同速规则沿用当前实现。

**为什么用取整前的值**　整数面板已经丢掉了小数，继续用它计算迅捷会偏一格。显示和排序用同一个整数，玩家能用看到的速度解释出手先后。

### 回血时点

1. **首回合**　在双方在场单位就绪后、允许下达第 1 回合指令前执行一次。现有普通新战斗满血开场，实际恢复是 0。
2. **后续回合**　上一回合行动结束且战斗继续时，在新回合开放手动/自动指令前执行一次。仅拥有回血、`deployed === true`、`hp > 0` 且 `left === false` 的单位可恢复。按真实等级向下取整，0／1 级回 0。倒地、后备、已离场单位均跳过。战斗已结束无需再开启下一回合。
3. **当回合召唤**　进入本回合指令阶段时已经在场的灵宠可以回血。行动结算中刚召唤上场的宠保留现有本场气血，最早等到下一回合开始且它仍符合条件时才回血。同回合抓取也不会触发回血。
4. **结算与展示**　由逻辑的新回合入口触发一次，查看面板、重绘、计时和开关自动不重复触发。保留上一回合动画的血条过程，新回合可操作前同步恢复后的血量。正恢复量日志带回合和单位，0 恢复不刷提示。

**为什么放在指令前**　先完成回血，玩家和自动战斗看到的是本轮实际血量。召唤在行动阶段发生，刚入场的宠物自然等到下一个指令阶段才有机会回。

**逻辑测试**　含以下可复现断言：

- 用能区分取整先后的低等级小数用例。例如真实 2 级，基础攻击 20.6 加 0.8 后为 21；基础防御 20.4 加 1.2 后为 22。覆盖无技能、0／1／20 级及敌方现有整数基础值。
- 回合边界验证首回合最多一次、先回血再允许指令、满血与低级为零、缺血不足时只回到上限、后备/离场/倒地排除、当回合召唤无即刻回血、下回合可回血。模拟手动和自动推进，并核对胜负后不再触发。
- 用真实抓取、召唤、换下再上、升级、加点及快照读回路径验证有效值未泄入携带数据。读原 v4 正常，保存仍是 v4 基础值，同一资料经再次开战和刷新有效值一致。

**华周怎么点**

1. 打开隔离的试玩入口，在「宠物 → 属性」分别选 A 和 B，核对两组三项及气血上限；重复打开和刷新，数字不增加。
2. 用同一对手分别打两场。观察 A 在对手之后、B 在对手之前行动。让两宠受伤并推进下一轮指令，核对血条和日志，B 到下一轮时才回血。
3. 让受伤的带回血宠在本轮被召唤，观察上场气血保留。等下一轮继续出指令，只有仍在场且存活的带技能宠回血。再试 0／1 级样本，受伤后进入下一轮都不回血。
